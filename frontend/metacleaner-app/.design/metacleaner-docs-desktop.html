Úvod

Začněte pracovat s Metadoc API

Vítejte v dokumentaci Metadoc API – RESTful rozhraní pro automatizované čištění a správu metadat souborů. API umožňuje nahrávat soubory, odstraňovat citlivá metadata (GPS, EXIF, IPTC) a stahovat vyčištěné verze přímo z vašich aplikací.

Base URL

https://docs.metacleaner.app/v1

Bezpečné čištění

Odstraní GPS, EXIF a IPTC metadata bez poškození kvality souboru.

Asynchronní zpracování

Soubory se zpracovávají na pozadí. Sledujte průběh pomocí job_id.

Dávkové zpracování

Zpracujte více souborů najednou pomocí sessions a file_ids.

Podporované formáty

JPGPNGHEICWEBPMP4MOV

Rychlý start – tok volání

1

Nahrajte soubory

Volejte POST /files/upload — získáte file_id pro každý soubor.

2

Spusťte čištění

Volejte POST /files/clean s file_ids — získáte job_id.

3

Sledujte průběh

Volejte GET /jobs/{'{job_id}'}/status dokud stav není completed.

4

Stáhněte výsledek

Volejte GET /files/{'{file_id}'}/download pro stažení vyčištěného souboru.

Limity požadavků (Rate Limiting)

Každý API klíč je omezen na 120 požadavků za minutu. Při překročení limitu vrátí API odpověď 429 Too Many Requests. Limit se resetuje každou minutu.

Autentizace

Zabezpečení přístupu k API pomocí API klíčů

Metadoc API používá autentizaci pomocí Bearer tokenů. Každý požadavek musí obsahovat platný API klíč v HTTP hlavičce Authorization.

Authorization Header

Authorization: Bearer YOUR_API_KEY

Jak získat API klíč

API klíč vygenerujete ve svém účtu v sekci Nastavení → API Klíče. Klíč se zobrazí pouze jednou při vytvoření – uložte jej na bezpečné místo.

Příklad autentizovaného požadavku (cURL)

curl -X GET \
  "https://docs.metacleaner.app/v1/jobs/job_xyz/status" \
  -H "Authorization: Bearer YOUR_API_KEY"

Bezpečnostní doporučení

Nikdy nezahrnujte API klíč přímo do kódu na straně klienta (JavaScript, mobilní aplikace).

Ukládejte klíč jako proměnnou prostředí (ENV) nebo použijte správce tajemství.

Při podezření na kompromitaci klíče jej okamžitě revokujte a vygenerujte nový v nastavení účtu.

Veškerá komunikace probíhá přes HTTPS. Požadavky přes HTTP jsou automaticky odmítnuty.

Chybové kódy

Přehled všech stavových kódů a jejich významů

Metadoc API používá standardní HTTP stavové kódy k indikaci úspěchu nebo neúspěchu požadavku. Všechny chybové odpovědi mají konzistentní JSON strukturu s poli status, code a message.

Struktura chybové odpovědi

{
"status": "error",
"code": "ERROR_CODE", // Strojově čitelný kód chyby
"message": "Human readable message", // Popis pro vývojáře
"details": { ... } // Volitelné doplňující informace
}

HTTP Stavové kódy

2xx

Úspěch

Požadavek byl úspěšně zpracován.

4xx

Chyba klienta

Neplatný požadavek ze strany klienta.

5xx

Chyba serveru

Neočekávaná chyba na straně serveru.

3xx

Přesměrování

Klient by měl přesměrovat požadavek.

Kompletní přehled chybových kódů

HTTP Kód chyby Popis Řešení
200 OK Požadavek úspěšný —
202 ACCEPTED Asynchronní úloha přijata ke zpracování Sledujte stav přes /status
400 BAD_REQUEST Chybný formát nebo chybějící parametry Zkontrolujte tělo požadavku a parametry
401 INVALID_API_KEY Chybějící nebo neplatný API klíč Ověřte platnost API klíče v hlavičce
403 FORBIDDEN Nedostatečná oprávnění pro operaci Zkontrolujte plán a oprávnění klíče
404 FILE_NOT_FOUND Soubor nebo úloha nebyla nalezena Ověřte správnost file_id nebo job_id
409 CONFLICT Soubor již byl zpracován nebo je konflikt Nahrajte soubor znovu s novým session_id
413 FILE_TOO_LARGE Soubor překračuje maximální povolenou velikost Soubor musí být menší než 500 MB
415 UNSUPPORTED_FORMAT Nepodporovaný formát souboru Použijte JPG, PNG, HEIC, WEBP, MP4 nebo MOV
422 VALIDATION_ERROR Neplatné hodnoty parametrů v požadavku Zkontrolujte typy a hodnoty všech parametrů
429 RATE_LIMIT_EXCEEDED Překročen limit požadavků (120/min) Počkejte na reset limitu nebo zpomalte volání
500 INTERNAL_ERROR Neočekávaná interní chyba serveru Zkuste znovu za chvíli nebo kontaktujte podporu
503 SERVICE_UNAVAILABLE Služba je dočasně nedostupná (údržba) Sledujte status stránku a zkuste znovu

Doporučená strategie opakování (Retry)

Pro chyby 429 a 5xx doporučujeme implementovat exponenciální zpětné přihlášení (exponential backoff):

# Čekací doby: 1s → 2s → 4s → 8s → 16s
delay = 2 ** attempt # max 5 pokusů
