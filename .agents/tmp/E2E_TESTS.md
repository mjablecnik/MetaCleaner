## ⚠️ Dominant root cause — the suite is broadly stale after the auth/route refactor

Two recent app changes broke most authenticated specs:

1. **The main app routes are now auth-protected.** `src/routes/+page.ts` (home `/`),
   `reports/+layout.ts`, `report/+layout.ts`, `settings/+layout.ts`, `subscription/+page.ts`,
   and `docs/+layout.ts` all call `guardProtectedRoute()`, which redirects to `/login` when
   `!authStore.isAuthenticated`.
2. **Auth restore no longer trusts a localStorage access token.** `auth.svelte.ts._restore()`
   now **purges `mc_access_token`** ("Access token is never persisted… purge any value left by
   older code") and re-authenticates **only** by exchanging `mc_refresh_token` via a silent
   `refresh()` → `POST {PUBLIC_API_URL}/api/auth/refresh`. `isAuthenticated` is
   `_accessToken !== null`, which is only set after that refresh call succeeds.

Consequences:
- Specs that `goto('/')` (and the whole step1–step5 wizard) **never authenticate** → redirected
  to `/login` → the upload zone never renders → `#dropzone-file-input` `setInputFiles` **times
  out at 30 s**, headings/buttons "not found".
- `docs-sidebar-highlight.spec.ts` **does** inject `mc_access_token`/`mc_refresh_token`, but the
  access token is purged and the refresh endpoint is **not mocked**, so `refresh()` fails →
  `_clear()` → unauthenticated → redirect → `aside` (the docs sidebar) never appears. All 17 docs
  tests fail.

### The fix (shared auth bootstrap) — applies to every authenticated spec
Add a helper, e.g. `e2e/helpers/auth.ts`, used in `beforeEach` **before** `goto`:
```ts
export async function injectAuth(page) {
  await page.addInitScript(() => {
    const farFuture = String(Date.now() + 3600 * 1000);
    localStorage.setItem('mc_refresh_token', 'fake-refresh-token');
    localStorage.setItem('mc_token_expires_at', farFuture);
    // remember-me defaults to true (REMEMBER_KEY !== 'false')
  });
  await page.route('**/api/auth/refresh', (route) =>
    route.fulfill({
      status: 200, contentType: 'application/json',
      body: JSON.stringify({
        access_token: 'mock-access-token',
        refresh_token: 'fake-refresh-token',
        expires_in: 3600,
        user: { id: 'user-1', email: 'test@example.com', name: 'Test User' }
      })
    })
  );
  // Optional but recommended for pages that read the profile / subscription:
  await page.route('**/api/auth/me', (route) =>
    route.fulfill({ status: 200, contentType: 'application/json',
      body: JSON.stringify({ id: 'user-1', email: 'test@example.com', name: 'Test User' }) }));
}
```
> `addInitScript` runs before app JS, so the refresh token is present when `_restore()` runs and
> the mocked `/api/auth/refresh` makes `isAuthenticated` true before the guard decides.
> The existing `docs-sidebar` `injectAuth` (which only sets `mc_access_token`) must be replaced
> with this version.

## FAILING E2E tests

A run was sampled to **175 / 435 tests, at which point 85 failures** had already accumulated
across 10 spec files (`auth-navigation`, `auth-responsive`, `docs-sidebar-highlight`,
`email-verified`, `file-removal`, `file-validation`, `forgot-password`, `hamburger-menu`, `login`,
`navigation`). The run was stopped because every failing wizard/redirect test costs a full 30 s
timeout, and the cause was already conclusive and uniform. The unreached specs (`register`,
`reports`, `report-detail`, `responsive`, `step1-upload`, `step1-to-step2-transition`,
`step2-risk-analysis`, `step2-to-step5-complete-flow`, `step3-processing`, `step3-cancel`,
`step4-error`, `step5-results`, `step5-report-navigation`) all `goto('/')` or a protected route
without authenticating, so they fail by the **same** Group-A cause. Failures group by spec as follows:

### Group A — authenticated specs failing wholesale (auth bootstrap missing/broken)
Fix = add the shared auth bootstrap (above) in `beforeEach` before navigating.
- `step1-upload`, `step1-to-step2-transition`, `step2-risk-analysis`, `step2-to-step5-complete-flow`,
  `step3-processing`, `step3-cancel`, `step4-error`, `step5-results`, `step5-report-navigation`
  — all start at `/` (now protected); upload zone never renders (`#dropzone-file-input` 30 s timeout).
- `file-removal`, `file-validation` — same (`/` protected).
- `responsive`, `navigation` — exercise `/` and protected routes.
- `reports`, `report-detail` — `/reports`, `/report/[id]` now protected; no auth → redirect to `/login`.
- `docs-sidebar-highlight` — injects only `mc_access_token` (purged) and does not mock
  `/api/auth/refresh`; `aside` never renders. Replace its `injectAuth` with the new helper.
- `hamburger-menu` — exercises the authenticated NavBar/menu on `/`.

### Group B — public auth-page specs failing on selector/text drift (UI refactor)
These pages aren't protected; the assertions are stale vs the refreshed auth UI.
- `auth-navigation` — e.g. precondition `getByRole('button', { name: /^sign in$/i })` not found;
  the login submit button is now `<i></i> {tx('auth.login.submit.idle')}` (icon + i18n text) —
  re-derive the expected accessible name; verify the "Sign up"/"Sign in" nav + footer link labels.
- `auth-responsive` — branding panel / mobile hero / "form elements" selectors changed; re-check
  `#email-input`, `#password-input`, and the submit button's role-name.
- `email-verified` — **strict-mode violation**: `'Account created'` now resolves to 2 elements
  (a `<span>` stepper label + a `<p>`). Scope with `getByRole('heading'/'paragraph')` or `.first()`,
  and re-verify the stepper/stats text.
- `login`, `register`, `forgot-password` — partial failures from the same form/label drift;
  re-check submit-button names, error/loading text keys, and step-progress card selectors.

> **Verification note:** the `/`, `/reports`, `/report`, `/docs`, `/settings`, `/subscription`
> guards are intentional product behaviour (the app requires login), so the correct remedy is to
> **update the tests** to authenticate — not to remove the guards. Before fixing, re-run and
> confirm each Group-B failure is selector drift (not a real regression) by viewing the page.
