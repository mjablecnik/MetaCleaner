## FAILING stories (unhandled errors → exit 1)

**Root cause (single systemic issue):** during Storybook teardown, `@storybook/addon-svelte-csf`
+ Svelte 5 re-runs the story's reactive graph with props reset to `undefined` just before
unmount. Each of these components reads a **field of a prop object/array** in a `$derived` or
directly in the template **without a null guard**, so the final reactive pass throws
`TypeError: Cannot read properties of undefined (reading '…')`. The assertions still pass, but
the thrown errors are collected as unhandled and fail the process.

18 components throw (≈68 errors total across their stories):

| Component | Line(s) | Undefined access | Suggested guard |

| `sections/Step4Error/ErrorDetailAccordion.svelte` | 51, 128 | `error.fileName` | `error?.fileName` |
| `sections/Step3Processing/components/FileProcessingRow.svelte` | 68, 215 | `file.status` | `file?.status` / guard derived |
| `reports/components/ReportCard.svelte` | 46 | `report.tags` / `report.hasGps` | `report?.tags`, `report?.hasGps` |
| `reports/components/ReportTableRow.svelte` | 58 | `report.tags` | `report?.tags` |

| `reports/sections/ReportsTable.svelte` | 63, 138 | `reports.length` | `reports?.length` |

> Fix approach is uniform: make prop reads defensive (optional chaining / `?? []` / `{#if prop?.x}`)
> so the teardown re-render with `undefined` props is a no-op instead of a throw. This does not
> change production rendering (props are always defined at runtime).
